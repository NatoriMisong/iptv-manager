# TVB 无线新闻与无线财经

| 内置频道名称 | 标识 | 保存的官方来源页 |
|---|---|---|
| 无线新闻 | C | <https://news.tvb.com/tc/live/C> |
| 无线财经 | F | <https://news.tvb.com/tc/live/F> |

在管理页“添加频道 → 内置直播源 → 无线新闻”选择添加。数据库保存官网页，来源类型为 `builtin`，`provider_id=tvb`，`provider_channel_id` 为 `C` 或 `F`，默认中继。官方接口和 Cookie 逻辑由 `internal/provider/tvb.go` 独立处理。添加频道的来源类型不再提供单独的 TVB 选项。导出的 M3U 使用本服务固定播放入口，不能把临时签名 M3U8 当作永久来源保存。

## 官网播放流程

1. 官网使用 `GET https://news.tvb.com/app/public/live/channels` 获取目录；本服务的内置目录固定提供 C、F 两路。
2. 首次播放时，请求 `POST https://news.tvb.com/app/public/live/stream/C` 或 `/F`，读取 `stream_url`、`expire_time`、`refresh_interval`。无需账户 Cookie 即可取得播放信息。
3. 中继获取签名 HLS 主清单，保存 CDN 下发的 `hdntl` Cookie；后续清单和资源请求使用同一频道的 Cookie jar，按域名、路径和有效期发送、更新。请求使用官网 Referer、Origin 和浏览器 User-Agent。
4. 原样保留上游画质、音轨与标准 HLS AES-128 加密，改写清单、密钥和分片地址至本服务。播放器负责解码；服务器不解密、不转码、不重新切片。

接口响应中的 `header_json` 是上游响应元数据，不当作请求头或 Cookie 重放。所有解析及中继请求沿用频道的代理配置，TVB 资源和重定向限制在 HTTPS 的 TVB 域名范围。

CDN 主机为 `prd-vcache.edge-global.akamai.tvb.com`，C、F 分别使用 `ott_I-NEWS_h264`、`ott_NEVT1_h264` 路径。URL 包含临时签名，必须使用完整返回地址。来源及地区限制可能随出口变化，某一出口可播不代表所有地区可播放。

## 会话及刷新

- C、F 各自维护内存会话，避免同名 Cookie 互相覆盖。同频道并发首次请求合并为一次接口调用，TVB 接口初始化最多并行两路。
- 缓存有效期取官方到期时间、建议刷新周期与一小时上限的最早值，同时检查已取得的认证 Cookie 是否失效。仅由播放请求触发获取或更新，不设置后台定时任务。
- 过期的音视频清单引用按原画质和音轨定位新清单，同一轮更新共用新会话。清单返回 401/403 时最多重新获取并重试一次；更新后仍拒绝访问，短暂冷却后再允许重试。旧分片或密钥不会被替换成其他资源。
- 网页“刷新”清空该频道的临时地址、Cookie、资源引用和分片缓存，并取消旧会话中的请求。旧链接返回 410；下次打开频道重新获取。重启、修改来源或代理同样不会沿用旧会话。
- 直连返回签名地址的 HTTP 307 跳转，由播放器自行接收和维护 Cookie，可能受客户端网络及来源出口约束影响，默认推荐中继。
- 日志记录解析开始、成功、失败、到期时间、Cookie 建立和网络错误类别，不输出签名 URL 或 Cookie 值。解析错误短暂缓存，避免连续失败时频繁调用接口。

## 已知限制

- TVB 密钥站点有间歇性的 `TLS handshake failure`。仅针对这一握手错误，媒体 GET 最多额外重试两次，受同一 30 秒请求时限约束；保留 TLS 证书校验，不降低 TLS 配置。其他网络错误及持续失败正常返回错误。
- 配置备份只包含官网页，不包含播放令牌、签名或 Cookie。
- 过期及拒绝访问后的恢复流程由模拟来源回归测试覆盖；真实签名到期后播放器能否无缝恢复，取决于播放器行为，需要在实际环境中观察。

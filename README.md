# IPTV Manager

面向个人使用的轻量 IPTV 管理服务。统一管理通用 HTTP/HLS 直播、可定时更新的 M3U 订阅、网站电视来源以及 YouTube 直播，生成固定的 M3U 播放列表。每个频道都可以选择客户端直连或服务器中继，适合 VLC、电脑和电视。

设计目标是 Linux x64、1 核 CPU、1 GB 内存、1–2 台观看设备。主程序使用 Go，配置保存在 SQLite；yt-dlp 仅用于 YouTube 功能。通用直播和 M3U 订阅完全跳过 yt-dlp，视频由 Go 流式转发，不运行 FFmpeg、不重新切片、不转码。

自动测试基于本地模拟来源；真实直播、Docker 容器和目标服务器上的表现需按下文“部署后验收”自行确认。

## 功能与边界

- 中文网页管理频道：单个或批量添加、修改、删除、启停、排序、分组和图标。
- 通用直播源：HTTP/HTTPS HLS（M3U8）及 HTTP 媒体流，原始地址直连或完整中继。
- 网站直播源：澳视澳门（TDM）11 路电视、无线新闻（TVB）的无线新闻 C 与无线财经 F、HOY 76/77/78，以及香港卫视；可勾选添加并选择直连或中继，按来源与频道标识去重。TVB、HOY 仅在网站直播源中提供。
- TVB、HOY 按播放请求获取临时地址及来源认证信息，过期后按需更新，不做后台定时刷新；手动刷新会清除该频道的会话及媒体缓存。
- M3U 订阅：新增、修改、删除、立即同步、定时更新；保留频道播放设置和稳定 ID，同步失败保留原配置。
- 随机且固定的频道 ID，排序和编辑不会把原播放地址指向其他频道。
- 一个固定的 M3U 订阅地址；每个频道按自己设置的播放方式工作，默认服务器中继。
- “代理设置”页面集中管理 HTTP、HTTPS、SOCKS5 出站代理，可手动测试出口 IP；频道和 M3U 订阅按名称选择代理，网站直播源在“网站直播源”页面按来源统一设置。
- YouTube 功能：画质上限、来源缓存、提前过期、按需重新解析及手动刷新。
- YouTube 同频道解析请求合并；全局最多一个 yt-dlp 解析进程；有限队列和解析超时。
- HLS 子清单和资源地址改写，带令牌的媒体转发、范围请求和有限分片缓存。
- 管理密码、会话鉴权、CSRF 防护、播放令牌与令牌轮换。
- 月度中继流量统计、预算提示、JSON 配置导入导出。

**YouTube 功能支持同一格式包含音视频的 HLS，以及通过原始主清单关联独立音轨的 HLS。** 后一种情况下，程序选择画质上限以内的视频，核对主清单中的 `AUDIO` 分组，只保留该视频和关联音轨，由 VLC 同步播放。音轨在 yt-dlp 数据中缺少编码字段不会单独导致拒绝，但必须在主清单中验证关联。没有合适 HLS、没有有效音轨关联、只有 DASH 或需要转码时，会给出明确错误。当前不支持录制、回看、EPG、自动跟随频道的新直播、代理故障时自动切换出口，也不统计精确在线设备人数。

YouTube 功能的两个初始示例频道使用固定视频 ID：

| 初始名称 | 来源 |
|---|---|
| 中天新闻 | <https://www.youtube.com/watch?v=vr3XyVCR4T0> |
| 东森新闻 51 | <https://www.youtube.com/watch?v=V1p33hqPrUk> |

可以在管理页修改名称。直播方更换视频 ID 后，需要更新频道来源；只要编辑原频道，订阅中的频道 ID 就保持不变。初始频道只在新数据库第一次启动时创建，删除后不会在下次启动时重新出现。

## 通用直播与 M3U 订阅

单个直播地址：点击“添加频道”，选择“通用直播源（M3U8 / HTTP）”，填写名称及公网 HTTP/HTTPS 直播地址，再选择直连或中继。批量添加也支持通用源，每批最多 100 行。HLS 中继会改写主清单、子清单、音轨、密钥、初始化段和分片；连续 HTTP 媒体流按连接转发，不缓存整路直播。

多个频道的 M3U 列表：打开“M3U 订阅”页面，填写列表 URL、名称和更新间隔，保存后立即同步。自动更新默认每 60 分钟，允许 5–10080 分钟；后台每分钟检查一次，最多同时获取一份列表。可暂停自动更新、手动“立即同步”，或删除订阅及其频道。获取列表时可选择一个已保存的代理；导入频道默认使用服务器中继、不走代理，也可逐个调整。

同步规则：

- 读取 `#EXTINF` 名称、`group-title`、`tvg-logo` 和 `tvg-id`，相对地址按最终列表 URL 解析。
- 有唯一 `tvg-id` 的频道使用它匹配，名称或播放地址变化后仍保留原 ID。没有 `tvg-id` 时按完整来源 URL 匹配；URL 变化会产生新频道。重复 `tvg-id` 对应不同 URL 时停止同步并报错，避免错误替换频道。
- 更新名称、分组、图标和地址，保留用户设置的播放方式、代理、排序和启停状态。订阅频道的来源字段由订阅管理；如需自行修改，另建一个手动频道。
- 来源中消失的频道标记失效并从输出订阅排除；后续重新出现时恢复原 ID。手动停用的频道仍保持停用。
- 网络失败、格式错误、空列表和数据库错误不会清空已有频道，管理页及日志显示失败原因。相同来源在不同订阅中分别管理。
- 每份列表最多 2 MB、1000 个有效频道；最多 20 个订阅，全项目最多保留 1000 个频道（包括失效频道）。超限会拒绝更新。

通用来源支持公网 HTTP/HTTPS，不支持 UDP、RTSP、RTMP、DRM 或列表中的自定义 Cookie/Referer/User-Agent 指令；不支持的地址条目会跳过并显示数量，全部无效则保留现有列表。内网、回环和云元数据地址不能作为中继/订阅来源，重定向和实际连接也会检查。配置的出站代理属于可信网络出口。订阅更新只下载列表，不预拉取每个频道的视频，也不会调用 yt-dlp。

## 网站直播源：澳视澳门

在“添加频道”的来源类型中选择“网站直播源”，选择“澳视澳门”，勾选需要的频道并设置播放方式后点击“添加所选频道”。默认勾选 91 至 96 台六路电视，三路 CGTN 和两路会议直播默认不选中，可按需勾选；分组名称也可以修改。

澳视澳门使用官网提供的原始 M3U8，由独立的 `internal/provider/tdm.go` 管理，不调用 yt-dlp。播放时按官网播放器的做法调用官方域名接口，把目录里的 `live3.tdm.com.mo` 换成当前出口可用的 CDN 域名（澳门以外通常是 `globallive.tdm.com.mo`），结果按出口缓存一小时，接口失败时沿用目录地址。网站来源频道的来源固定，添加后可编辑名称、分组、图标、播放方式和启停状态；代理在“网站直播源”页面按来源统一选择。重复添加跳过已有频道，不覆盖设置。网站来源清单随项目版本维护，不会定时访问官网；自定义地址可另建通用频道，可定时更新的列表使用“M3U 订阅”。

频道地址与已知限制见 [澳广视来源记录](docs/sources/tdm.md)，也可直接使用 [原始 M3U 列表](docs/sources/tdm.m3u)。

## 网站直播源：无线新闻（TVB）

在“添加频道 → 网站直播源”中选择“无线新闻”，勾选“无线新闻”（C）和“无线财经”（F），默认采用服务器中继。代理在“网站直播源”页面为整个来源统一选择。添加时只保存官网直播页，不请求播放接口、不调用 yt-dlp。

首次播放时获取临时签名地址；中继时自动保存 CDN 下发的 Cookie，主清单、音视频清单、密钥和分片共享该频道的会话。C、F 的 Cookie 相互隔离，仅保存在内存，不写入数据库、配置备份或日志。程序重启后，下次播放重新获取。

缓存按官方到期时间、建议有效期和 Cookie 状态判断，最长复用一小时。过期后由下一次播放或直播清单请求重新获取，**没有后台定时刷新**。清单遇到 401/403 时最多更新会话并重试一次，持续失败有短暂冷却。网页“刷新”立即撤销该频道的 Cookie、播放地址和媒体缓存，旧媒体链接失效；下一次打开频道重新获取，必要时在 VLC 中重开频道。

TVB 保留原始画质和音轨，由播放器选择；不进行切片或转码。直连会跳转到临时签名地址，需要播放器维护 Cookie、客户端能访问 TVB，且来源允许客户端出口使用，推荐先用中继。官方接口、Cookie 和会话逻辑集中在 [internal/provider/tvb.go](internal/provider/tvb.go)，HLS 中继与会话恢复流程由共用媒体层处理，接口流程及验证边界见 [TVB 来源记录](docs/sources/tvb.md)。

## 网站直播源：HOY

在“添加频道 → 网站直播源”中选择“HOY”，默认勾选 HOY 76、77、78，采用服务器中继，代理在“网站直播源”页面按来源统一选择。重复添加跳过已有频道，保留名称和播放设置。添加仅保存频道身份和官网直播页，不请求播放接口、不调用 yt-dlp。

首次播放调用官网 `liveCheckout` 接口，按频道单独保存内存签名。中继为主清单、子清单和媒体资源附加当前签名，保留原始画质和音轨，不转码。缓存最长一小时，并在官方签名到期前 30 秒失效；过期由下一次播放或清单请求更新。清单 401/403 的限次恢复、手动刷新和代理变更处理沿用 TVB 的会话方式，签名不写入数据库、备份或日志。

**需要直播 CDN 允许的地区出口。** 官方接口返回签名不代表媒体可用，不允许的地区会收到 403。直连返回带签名主清单的 307 跳转，播放器还需把签名用于后续清单和分片，普通播放器不一定支持，推荐中继。实现见 [internal/provider/hoy.go](internal/provider/hoy.go)，获取流程及已知限制见 [HOY 来源记录](docs/sources/hoy.md)。

## 网站直播源：香港卫视

在“添加频道 → 网站直播源”中选择“香港卫视”，默认勾选该频道并采用服务器中继，也可以选择客户端直连。代理在“网站直播源”页面统一设置；重复添加会跳过已有地址，不覆盖播放设置。

频道作为网站来源保存，由独立的 `internal/provider/hkstv.go` 提供官网 HTTPS HLS 主清单及请求头规则，复用通用媒体中继，不调用 YouTube 或 TVB 解析器，不转码。播放器或中继服务读取主清单后获取带 `hls_ctx` 的子清单及分片；保存频道时应保留不带临时参数的主清单地址。当前验证无需 Cookie，中继会自动使用普通浏览器 User-Agent。

地址、获取流程及验证结果见 [香港卫视来源记录](docs/sources/hkstv.md)，也提供 [原始 M3U 列表](docs/sources/hkstv.m3u)。

## 两种播放路径

| 路径 | 服务如何工作 | 客户端条件 | 服务器视频流量 |
|---|---|---|---|
| 服务器中继 | 通用源直接连接；YouTube、TVB、HOY 按需解析，再改写 HLS 资源并转发 | 能访问本服务的域名 | 有 |
| 客户端直连 | 通用源、TVB、HOY 返回 HTTP 307；YouTube 独立音轨来源返回筛选后的主清单 | 能访问原始来源，且来源允许该客户端出口使用；TVB 还需 Cookie 支持，HOY 需传递后续请求签名 | 通常没有 |

独立音轨的直连模式只由服务器获取并筛选主清单，不转发音视频分片；中继模式则改写视频、音轨及其分片地址。YouTube 的两种模式都会遵守画质上限。通用源保持原始清单，由播放器选择画质，不套用 YouTube 的格式筛选规则。

直连不是通过服务器解决客户端访问 YouTube 的问题。YouTube 临时 URL 可能绑定解析时的出口或要求额外请求信息，服务器解析成功也不能保证家庭网络的 VLC 能直连播放；失败时把该频道改为服务器中继。

“服务器中继”和“出站代理”是独立配置。服务器能直接访问来源时保持直连。中继模式仍然会让客户端只访问服务器。频道选择了代理时，来源解析（包括 yt-dlp 以及 TVB、HOY 的官网接口请求）、清单获取和中继媒体采用同一出口；代理改变后会重新解析。

来源过期或网络故障时，服务会清除失效解析缓存，在后续播放请求中重新解析。已经开始播放的 VLC 能否自动恢复取决于故障位置和播放器行为；必要时在管理页刷新来源，再重新打开频道。首版不承诺直播跨地址切换时无缝续播。

## Docker 部署

需要一台能访问所用直播源的 Linux x64 服务器（使用 YouTube 功能时还需能访问 YouTube），已安装 Docker Engine 和 Docker Compose 插件。程序通过 HTTP 提供服务，默认端口为 9000，可使用服务器 IP 或域名访问。使用域名时，A 记录应指向服务器；如果存在 AAAA 记录，IPv6 也需要正确可达。

获取项目并准备配置：

```bash
git clone https://github.com/NatoriMisong/iptv-manager.git
cd iptv-manager
cp .env.example .env
chmod 600 .env
```

编辑 `.env`，至少设置以下项目：

```dotenv
PUBLIC_URL=http://tv.example.com:9000
HTTP_BIND=0.0.0.0
HTTP_PORT=9000
ADMIN_PASSWORD='请替换为自己生成的高强度密码'
```

`PUBLIC_URL` 填写播放器实际访问的完整地址，例如 `http://tv.example.com:9000` 或 `http://你的服务器IP:9000`，不能附加 `/youtube` 等路径。`HTTP_BIND` 和 `HTTP_PORT` 控制 Docker 在宿主机发布的地址与端口；修改端口后，同步修改 `PUBLIC_URL`。管理密码必须为 12–72 **字节**；中文字符通常占多个字节。可用 `openssl rand -hex 24` 生成随机密码，然后保存到密码管理器中。

放行服务器防火墙和云平台安全组中的入站 TCP 9000（修改端口时使用对应端口），然后启动：

```bash
docker compose up -d --build
docker compose logs --tail=100 app
```

打开 `http://tv.example.com:9000`，使用 `.env` 中设置的初始密码登录。默认只启动应用容器，证书和 HTTPS 由使用者按需自行配置。

默认 Compose 项目名为 `iptv-manager`，数据卷为 `iptv-manager_data`，数据库为 `/data/iptv-manager.db`。首次启动直接创建完整数据库结构并初始化管理密码、播放令牌和示例频道。按全新实例部署即可，无需保留其他项目的目录名或数据卷。

查看或停止部署：

```bash
docker compose ps
docker compose down
```

默认端口的健康检查：

```bash
curl -fsS http://127.0.0.1:9000/healthz
```

`/healthz` 返回 `ok` 表示应用和数据库能够响应，不代表 YouTube 或某个频道已验证可播。

### 可选：自行使用 Nginx 提供 HTTPS

需要 HTTPS 时，自行安装 Nginx、配置域名和证书，将 HTTPS 请求转发到应用的 HTTP 端口。若 Nginx 运行在同一宿主机，可以将 `.env` 的 `HTTP_BIND` 改为 `127.0.0.1`，保留 `HTTP_PORT=9000`，然后执行 `docker compose up -d app` 使端口配置生效。

在已配置好证书的 Nginx `server` 块中加入：

```nginx
location / {
    proxy_pass http://127.0.0.1:9000;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 90s;
}
```

保留原始 `Host`（包括非默认端口），以便管理请求的来源验证正确工作。如果 Nginx 也运行在另一个容器中，`127.0.0.1` 指向该代理容器自身；应将两个服务连接到同一 Docker 网络，再使用 `http://app:9000` 作为上游。

首次部署时，将 `PUBLIC_URL` 设为 `https://tv.example.com`。已有数据库时，在管理页将“公开访问地址”改为对应 HTTPS 地址，再执行 `docker compose restart app`，让自动 Cookie 设置生效，并重新复制订阅。应用不把任意转发请求头当作可信公网域名，订阅地址以保存的“公开访问地址”为准。不要对带播放令牌的清单或媒体地址配置公共 CDN 缓存。

## 首次使用与 VLC

1. 登录管理页，在“服务设置”中核对服务访问地址，例如 `http://tv.example.com:9000`。
2. 保持画质上限 720p，频道播放方式为“服务器中继”、代理为直连。
3. 在频道列表核对两个初始来源。点击“刷新”会使缓存失效，下一次播放时重新解析。
4. 点击“复制订阅地址”。在桌面 VLC 中打开 **媒体 → 打开网络串流**，粘贴地址并播放；Windows 快捷键是 `Ctrl+N`。
5. 打开 VLC 播放列表切换频道。Android TV 上可在 VLC 的网络串流入口输入相同地址；菜单名称可能因版本不同而变化。
6. 电脑能够访问 YouTube 时，可把某个频道的播放方式改为“客户端直连”再试。订阅地址不变，播放器重新加载列表即可。

首次播放通常比后续打开更慢，因为 yt-dlp 需要获取并选择来源。只有实际打开频道才解析和拉取媒体；单纯导入 M3U 不会持续拉流所有频道。

订阅地址只有一个，所有频道共用：

```text
http://tv.example.com:9000/playlist.m3u?token=你的播放令牌
```

每个频道在编辑中选择“服务器中继”或“客户端直连”，订阅里的播放链接按该设置工作。

- `default`：先使用单个频道的设置，频道选择继承时使用全局设置。
- `relay`：强制所有启用的频道经过服务器中继。
- `direct`：强制所有启用的频道尝试客户端直连。

订阅和其中的频道、媒体地址都包含播放令牌，拥有地址即可播放。请只保存在自己的设备中。重置令牌后，旧地址和当前媒体请求会失效，需要在设备上重新导入订阅；修改管理密码不会改变播放令牌。

## 批量添加频道

在频道管理页点击“批量添加”，先选择“通用直播源”或“YouTube 直播”，每行填写一个对应类型的直播链接，也可以填写 `频道名称,链接`：

```text
中天新闻,https://www.youtube.com/watch?v=vr3XyVCR4T0
东森新闻 51，https://youtu.be/V1p33hqPrUk
```

- 名称与链接之间支持英文逗号、中文逗号或 Tab；名称本身请勿使用这些分隔符。不带名称时，通用源使用来源域名，YouTube 使用 `YouTube 视频ID`，添加后可以编辑名称。支持 `youtube.com/watch?v=…` 和 `youtu.be/…` 链接。
- 每批最多 100 个非空行、总文本最多 256 KB；空行忽略。可统一指定分组、播放方式和画质上限，新频道默认启用、统一使用所选代理（默认直连），按输入顺序追加到列表末尾。
- 按视频链接去重：短链接、标准链接以及附加分享参数会归一化；与已有频道或本批次前面成功添加的频道重复时跳过，不修改原频道。首次启动已有上述两个示例频道，再粘贴它们会显示“已跳过”。
- 提交后显示新增、跳过、失败数量和逐行结果；无效链接或名称只影响对应行。修正错误行后可以再次提交，已添加的链接会自动跳过。超过批量限制或公共设置无效时整批拒绝；数据库写入失败时整批回滚。
- 添加只保存频道配置，不访问 YouTube 获取标题或验证开播状态；在实际播放时才解析来源。频道加入后，播放器重新加载原订阅地址即可获取新列表。

批量添加是追加操作。页面底部的“导入配置”用于恢复完整 JSON 备份，会替换当前频道和设置。

管理 API 为 `POST /api/channels/bulk`，与其他管理接口一样需要登录会话和 `X-CSRF-Token`，请求使用 JSON：

```json
{"text":"频道名称,https://youtu.be/vr3XyVCR4T0\nhttps://youtu.be/V1p33hqPrUk","group":"新闻","mode":"inherit","quality":0}
```

`source_type` 可设为 `youtube`（默认）或 `stream`。通用源的 URL 按完整地址去重并保留签名参数。网站来源使用独立身份参数，由服务器从目录取得名称和 URL，无需提交文本地址：

```json
{"source_type":"builtin","provider_id":"tvb","channel_ids":["C","F"],"group":"无线新闻","mode":"relay"}
```

网站来源目录来自已登录的 `GET /api/builtin-sources`。网站来源频道保存 `provider_id` 与 `provider_channel_id`；编辑时保留来源身份和 URL，不能把它改成另一个来源。旧的 `source_type: "tvb"` 新建请求不再支持。

返回 `added`、`skipped`、`failed` 计数及 `results` 逐行结果（原始行号 `line`、`status`、`message`、名称、规范化链接和已有/新建的频道 ID）。单行失败以 HTTP 200 返回批次结果；请求整体无效返回 400，数据库错误返回 500。

## 设置与环境变量

频道、画质、出站代理、服务访问地址和流量预算通过网页管理，保存在 SQLite 中。环境变量负责进程和首次启动配置：

| 变量 | 默认值 | 含义 |
|---|---|---|
| `DATA_DIR` | `./data` | 数据目录；Docker 中由 Compose 指定持久化位置 |
| `LISTEN_ADDR` | `127.0.0.1:9000` | 原生进程监听地址；容器内需监听所有容器网卡 |
| `ADMIN_PASSWORD` | 无 | 仅数据库尚无管理员密码时必填，长度 12–72 字节 |
| `ADMIN_PASSWORD_FILE` | 无 | 原生程序或自定义容器部署可从该文件读取初始密码；设置后优先于 `ADMIN_PASSWORD` |
| `PUBLIC_URL` | 无 | 当数据库服务地址为空时初始化，例如 `http://tv.example.com:9000` |
| `YTDLP_BIN` | `yt-dlp` | yt-dlp 可执行文件路径 |
| `JS_RUNTIME` | `node` | yt-dlp 使用的 JavaScript 运行时配置 |
| `COOKIES_FILE` | 无 | 可选 Netscape 格式 Cookies 文件路径，必须在运行环境内可读 |
| `CACHE_MB` | `32` | 分片缓存容量，单位 MiB，允许 0–128，0 关闭缓存；不是整个应用的内存限制 |
| `LOG_LEVEL` | `info` | 日志级别：`debug`、`info`、`warn`、`error`；`info` 包含解析开始、成功和失败，`debug` 额外记录缓存命中与排队耗时 |
| `SECURE_COOKIES` | 根据 HTTPS 自动判断 | 管理 Cookie 的 Secure 标记；HTTPS 部署应启用 |
| `HTTP_BIND` | `0.0.0.0` | Compose 发布端口的宿主机绑定地址；同机 Nginx 反代可改为 `127.0.0.1` |
| `HTTP_PORT` | `9000` | Compose 发布的宿主机 HTTP 端口，容器内仍为 9000 |
| `YTDLP_VERSION` | 见 `.env.example` | Compose 构建参数，锁定 yt-dlp 的 PyPI 版本，不是运行时自动更新开关 |

`.env` 只会向容器传递 Compose 文件明确映射的变量。使用 `COOKIES_FILE`、`ADMIN_PASSWORD_FILE` 等可选配置时，需要在自己的 Compose 覆盖文件中添加对应 `environment` 和只读文件挂载；仅在 `.env` 添加名称并不自动生效。默认 Compose 仍要求提供 `ADMIN_PASSWORD`，文件形式的初始化需要同步调整该环境变量映射。

已有数据库时，重新设置 `ADMIN_PASSWORD` **不会重置密码**。日常修改密码请使用管理页“修改管理密码”；修改后所有管理会话退出登录。重启应用也会清空管理会话，但不会删除配置和播放令牌。

已有服务访问地址时，修改 `.env` 中的 `PUBLIC_URL` 不覆盖数据库设置。更换域名后，在管理页更新服务访问地址，再重新复制订阅。切换 HTTP/HTTPS 后，重启应用以更新自动 Cookie 设置；HTTP 使用非 Secure Cookie，HTTPS 使用 Secure Cookie。

## 代理设置

“代理设置”页面集中保存出站代理，每条包含名称、协议（HTTP、HTTPS 或 SOCKS5）、主机、端口和可选的用户名、密码，最多 50 条。没有全局默认代理：

- 通用直播和 YouTube 频道在编辑时选择“直连”或某个代理；批量添加可为整批统一选择，M3U 订阅导入的频道默认直连，可逐个修改。
- M3U 订阅自身可选择下载列表时使用的代理，与其频道的代理互不影响。
- 网站直播源（澳视澳门、TVB、HOY、香港卫视）在“网站直播源”页面为每个来源选择一个代理，该来源的全部频道共用，频道编辑中不再单独选择。
- 频道选择了代理后，解析播放地址、获取清单和中继分片全部经过该代理；修改代理地址后，相关频道会重新解析。

每条代理旁的“测试”按钮会让服务器通过该代理请求 `https://ipip.info`，返回出口 IP 和耗时；测试只在手动点击时执行，单次 10 秒超时，同一时间只运行一个，失败不自动重试。删除被频道、订阅或网站来源引用的代理会被拒绝并提示引用数，先改掉引用再删除。

容器中的 `127.0.0.1` 指容器自身，不能直接用它访问宿主机上的代理。密码中的 `@`、`:` 等特殊字符直接填写即可，程序会自行编码。

## 资源与流量

应用不解码和重新编码视频，正常转发主要消耗网络带宽。1 核 1 GB 是本项目的设计目标，不是所有 YouTube 来源都能稳定运行的承诺；需要在实际服务器上观察首次解析、两路并发和持续播放时的内存峰值。

- 一次只运行一个解析任务，避免两个设备同时打开频道时启动多个 Python/JavaScript 解析进程。
- 默认 32 MiB 分片缓存不代表总内存只有 32 MiB。Go、SQLite、网络缓冲、进行中的请求及 yt-dlp/JavaScript 子进程都额外占用内存。
- 相同频道可共享解析结果及短期缓存。不同频道、不同画质分别取流；超过缓存大小的分片不会被无限留在内存。
- 无人观看时不主动下载视频。播放器可能预取若干分片，因此关闭界面与最后一个网络请求之间可能有短暂间隔。
- 720p 是清晰度上限，不是固定码率。若没有符合上限的可用格式，服务不会自动转码或偷偷选择更高分辨率。

默认 Compose 将应用容器内存限制为 640 MiB、CPU 限制为 1 核。镜像将 Go 的软内存目标设为 192 MiB；它不约束外部 Python/Node 进程，也不是整个容器的硬内存上限。给宿主机保留的余量仍需结合其他服务评估。

按每台设备平均 5 Mbps 估算，一个观看小时约产生 **2.25 GB** 服务器视频出站流量。一台设备每天 4 小时、30 天约 270 GB；两台设备各观看相同时长约 540 GB，另留协议和重试余量。两台同看一个频道时，发给各自设备的出站流量仍分别计算。

30 Mbps 是线路标称带宽，两台 5 Mbps 播放平均约占 10 Mbps，但 HLS 分片下载具有突发性，还应为服务器其他业务留余量。服务器到家庭网络的线路质量，也会影响卡顿情况。

应用按 **UTC 自然月**统计中继发送的媒体/清单数据，约每 15 秒汇总写入 SQLite，正常退出时尽量冲刷。突然断电或强制杀死进程可能丢失最后尚未写入的小段统计。直连视频经过客户端与原始来源，不计入本服务的中继流量。

默认预算为 **800 GB**，仅用于提示，不会达到预算后强制断流。应用数据不包含所有 TLS、TCP、重传及其他服务流量，也不等于服务商的进出站计费口径。1 TB 套餐是否双向计费，应以服务商规则为准。

## 备份、更新与回退

管理页“导出配置”生成 JSON，包含频道、M3U 订阅、排序和设置。备份**包含播放令牌与代理凭据**，按敏感文件保存；不包含管理员密码哈希、历史流量或 YouTube Cookies 文件。导入会事务替换当前频道、M3U 订阅和设置；验证失败不做部分更新，管理员密码和历史流量保留。

导入会保留备份中的频道 ID 和播放令牌。如果导入另一个环境的备份，需要核对服务访问地址；该备份中的播放令牌也会成为当前有效令牌。

完整恢复还应备份持久化数据目录/卷和自行挂载的文件。SQLite 使用 WAL，**不要在应用运行时仅复制主 `.db` 文件并忽略 WAL**。简单做法是停止应用后完整备份数据目录，再启动应用。删除 Docker 容器不等于删除数据，但 `docker compose down -v` 会删除 Compose 管理的数据卷，应避免将它用于普通更新。

解析器版本在镜像构建时锁定，运行中不自动执行 `yt-dlp -U` 或下载更新脚本。YouTube 规则变化时，先记录当前镜像版本并备份，再修改 Dockerfile/构建参数中的 yt-dlp 版本，重建镜像并测试两个频道。不要只升级运行中容器里的工具，否则无法可靠复现和回退。

程序仅使用 `DATA_DIR` 下的 `iptv-manager.db`。0.4.0 的数据库结构为版本 5，**不兼容此前任何版本的数据库**：代理改为命名代理、全局默认播放方式取消，旧结构没有自动升级。从 0.3.x 或更早版本更新时，删除旧数据卷后全新部署，再在管理页重新添加频道、代理和订阅。

配置导出为版本 5，导入只接受版本 5。网页导入最大 32 MB。旧版本备份不能导入，其中的频道需要重新添加。

普通重建更新：

```bash
docker compose build --pull app
docker compose up -d app
```

更新前保留旧镜像或版本标签。回退使用旧镜像和同版本的数据备份；0.3.x 程序不能打开版本 5 数据库，0.4.0 也不能打开旧数据库。

## 本地开发与检查

需要 Go 1.24 或更高版本、Python、支持 JavaScript 的 yt-dlp 安装及 Node.js。项目 CI 和 Docker 构建使用明确的工具版本；本地开发建议与 Dockerfile 保持一致。SQLite 使用纯 Go 驱动，普通编译不需要系统 SQLite 或 C 编译器，竞态检查需要 Go 支持的 cgo/C 工具链。

首次本地运行可在终端临时设置密码，避免写入命令历史：

```bash
read -r -s -p '初始管理密码: ' ADMIN_PASSWORD
export ADMIN_PASSWORD
export PUBLIC_URL=http://127.0.0.1:9000
go run ./cmd/iptv-manager
```

打开 `http://127.0.0.1:9000`。原生程序默认仅监听本机；在服务器上直接运行并需要外部访问时，另设 `LISTEN_ADDR=0.0.0.0:9000`，同时将 `PUBLIC_URL` 设为客户端可访问的地址。

运行检查：

```bash
GOMAXPROCS=2 go test -p=1 ./...
GOMAXPROCS=2 go vet -p=1 ./...
GOMAXPROCS=2 go test -race -p=1 ./...
docker build -t iptv-manager:local .
```

自动测试使用本地伪造来源与 HTTP 服务验证行为，不依赖实际 YouTube 或电视台网络，也不证明具体直播在目标服务器可用。普通编译不需要 C 编译器；`go test -race` 需要 cgo 工具链，CI 已配置竞态检测和 Docker 构建。

### 部署后验收

成功返回 M3U8 不等于播放器已播通。清单获取成功不证明媒体 CDN 的连通性、播放地址的出口约束或 VLC 解码正常，建议按下面的顺序验收：

1. 使用 HTTP 域名或服务器 IP 加端口部署，登录并核对频道列表；频道先保持服务器中继。需要 HTTPS 时自行配置 Nginx。
2. 在 VLC 中打开一个频道，确认图像、声音、时间推进均正常，再逐个验证其余频道。
3. 出错时结合管理页的媒体错误状态、`docker compose logs --tail=100 app` 和 VLC 日志，区分来源解析、清单请求和媒体 CDN 请求三类问题。
4. 在客户端可访问来源时，把个别频道改为客户端直连验证；中继正常不代表直连一定可用。
5. 测试两台设备同频道及不同频道，观察 `docker stats`、流量与断线恢复；最后进行长时间持续播放测试。

YouTube 来源在部分网络出口会遇到“Sign in to confirm you’re not a bot”验证，此时服务返回明确的 503 验证错误；这是出口与 yt-dlp 层面的限制，不代表频道本身不可用。网站电视来源的地区和 CDN 限制见各[来源记录](docs/sources/)。

主要目录：

```text
cmd/iptv-manager/      进程入口、环境变量和服务生命周期
internal/core/      频道和设置的数据结构
internal/store/     SQLite、配置验证、备份与流量持久化
internal/source/    通用 HTTP 来源、网络边界和 M3U 列表解析
internal/subscription/ M3U 订阅手动/定时同步
internal/resolver/  YouTube 专用 yt-dlp、解析合并、缓存和频道状态
internal/media/     M3U、HLS 改写、媒体代理和有限缓存
internal/provider/  网站来源目录、解析和会话，每个供应方一个 Go 文件
internal/media/provider.go 网站来源的通用会话中继和恢复
internal/web/       管理 API 和嵌入式中文网页
```

新增网站来源的方法和接口约定见 [网站来源开发说明](docs/providers.md)。通常只需增加一个供应方 Go 文件、注册目录并补充对应测试，无需给前端增加新的来源类型。

## 常见问题

| 现象 | 检查方法 |
|---|---|
| 登录成功但订阅提示未设置服务地址 | 在服务设置中填写客户端实际能访问的 HTTP(S) 地址（域名或 IP，包含端口）；首次未配置 `PUBLIC_URL` 时不会猜测公网域名 |
| 显示未开播 | 确认链接仍是正在直播的视频，不能用预约、回放或已结束直播代替 |
| 提示没有符合条件的 HLS | 查看该频道在目标服务器的可用格式；尝试提高画质上限，但不会通过转码补齐来源 |
| YouTube 要求登录或机器人验证 | 核对服务器出口、yt-dlp 和 JavaScript 运行时版本；确有需要时配置自己的 Cookies 文件，并单独验证该出口可用性 |
| 中继正常，直连失败 | 客户端可能无法访问 YouTube，或来源绑定服务器出口；把该频道改回服务器中继 |
| 浏览器能登录，但 VLC 播放失败 | 核对访问地址、端口、播放令牌和来源状态；使用 HTTPS 时检查证书；在 VLC 日志区分清单请求失败和媒体请求失败 |
| HTTP 登录后立刻失效 | 核对已保存的公开访问地址是否仍为 HTTPS，或是否显式启用了 Secure Cookie；修改后重启应用，HTTP 下应为非 Secure Cookie |
| 换域名后订阅仍指向旧地址 | 修改数据库中的服务访问地址；已有设置不会被 `PUBLIC_URL` 自动覆盖 |
| 改了 `.env` 的密码仍无法登录 | 环境变量只初始化新数据库；已有实例通过管理页修改密码 |
| 持续卡顿或内存升高 | 先降低画质、仅播放一路，并用 `docker stats --no-stream` 查看应用及宿主机资源；检查线路和流量额度 |

查看应用日志和依赖版本：

```bash
docker compose logs --tail=100 app
docker compose exec app yt-dlp --version
docker compose exec app node --version
```

### 解析日志与格式筛选诊断

复现问题时先跟踪日志，再在 VLC 中打开一个频道：

```bash
docker compose logs -f --tail=100 app
```

默认 `LOG_LEVEL=info` 会记录：

- `直播来源解析开始`：频道 ID、YouTube 视频 ID、画质上限、代理类型及是否启用 Cookies。
- `直播来源解析成功`：总耗时（含排队）、选中分辨率、来源域名和过期时间。这里只表示取得了来源，媒体下载是否正常需继续看播放结果。`verify_audio_group=true` 表示使用独立音轨，还需要读取主清单验证关联。
- `直播来源解析失败`：明确的失败原因，例如额外验证、未直播、超时或没有匹配的 HLS。yt-dlp 有诊断输出时，同时记录脱敏后的错误/警告；进程异常退出时记录退出码，无法取得退出码时为 `-1`。
- `HLS 音视频关联成功`：主清单确认了视频对应的音轨，记录画质、音轨数量及匹配方式。`match=exact_url` 表示地址完全匹配；`match=youtube_itag` 表示临时地址变化后，通过 YouTube 格式编号、内容标识及视频参数确认了唯一的视频条目，采用当前清单的视频地址和音轨关联。
- `HLS 音轨关联验证失败`：记录选中的 `itag`、画质、主清单视频数量 `variants` 和匹配数量 `candidates`。视频不匹配时，一次请求最多自动重新解析并重试一次；同频道因此强制重新解析后有 30 秒冷却，避免播放器反复重试持续调用 yt-dlp。管理页手动刷新可清除冷却。歧义匹配、缺失音轨或资源地址不允许时直接失败，不放宽画质、音轨和地址校验。
- `HLS 格式筛选结果`：返回的格式总数、HLS 数量及各排除原因的数量，随后列出最多 20 个 HLS 格式的分辨率和编码信息；没有 HLS 时列出最多 20 个其他格式。

格式排除原因对应如下，多个条件不满足时按现有筛选顺序记录首个原因：

| 日志中的 `reason` | 含义 |
|---|---|
| `not_hls` | 格式协议不是 HLS |
| `invalid_media_url` | 媒体地址不符合允许的来源规则 |
| `missing_video_codec` | 未明确提供视频编码，或格式不含视频 |
| `missing_audio_master` | 视频未附带已知音频编码，且没有可用于验证音轨的有效主清单地址 |
| `unknown_height` | 未提供有效的视频高度 |
| `above_quality_limit` | 视频高度超过当前画质上限 |

例如，`hls_total=0` 表示此次返回的格式列表中没有 HLS；`above_quality_limit` 表示已有 HLS 被画质上限排除。日志只描述当前筛选结果，不会自动提高画质、合并音视频或转码。

需要查看缓存是否命中时，在 `.env` 中设置 `LOG_LEVEL=debug`，然后执行 `docker compose up -d app` 重新创建应用容器。默认级别不会为每次缓存命中重复打印解析日志。导入 M3U 不触发解析，管理页“刷新”仅清除缓存，随后需要重新打开频道才能看到新的解析过程。

日志不输出完整原始 M3U8、原始 JSON、Cookies 或代理凭据；yt-dlp 的 URL、认证头及敏感参数会脱敏，单次诊断输出限制为 8192 个字符。日志输出到标准错误，由 Docker 收集并按现有 Compose 配置轮转。

Cookies 文件不通过网页上传，也不在备份 JSON 中携带；如果使用，需要自行以只读方式挂载，并确保容器运行用户具有读取权限。每次解析会创建权限为 0600 的临时副本，允许 yt-dlp 更新自己的 cookie jar，执行结束后删除，原文件保持不变；文件上限为 1 MiB。它只能解决部分需要登录的情形，不能保证解决 YouTube 对出口或请求方式的限制。
